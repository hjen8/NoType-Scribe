## 專案知識沉澱 (Knowledge Sedimentation)

### ⚠️ 開機自動啟動機制的重要提醒
本專案的「開機自動隱藏啟動」高度依賴 Windows 工作排程器 (Task Scheduler) 與 VBS 腳本的配合。
- **核心路徑**：工作排程器任務 `\NoType_AutoStart` 綁定執行 `run_hidden.vbs`。
- **啟動鏈條**：`Task Scheduler` -> `run_hidden.vbs` -> `start_admin.bat` -> `pythonw.exe main.py`
- **防呆警告**：在執行「收工清理 (Cleanup)」時，**絕對不可將 `run_hidden.vbs` 或 `start_admin.bat` 視為無用暫存檔刪除**。若將其移除，將會導致隔日開機時工作排程器找不到檔案而跳出 Script 錯誤。

### 🧠 專案初創架構與核心設計決策 (Genesis Architecture)

這部分記錄了本專案在初始開發時，針對使用者獨特的工作環境與硬體配置所做的關鍵決策：

#### 1. API 引擎選擇：為何選用 Groq 而非本機 GPU 或 Gemini？
- **極致的低延遲需求**：語音打字輔助工具要求「毫秒級」的回饋。純地端運算（即便有 RTX 4080）處理 STT+LLM 仍可能耗時近 10 秒，無法滿足即時打字需求。
- **LPU 架構優勢**：Groq 採用專為大語言模型推理設計的 LPU (Language Processing Unit)，初次延遲 (Time to First Token) 極低，能有效消除打字時的「頓挫感」。
- **適才適所策略**：將「高頻、輕量」的打字語音辨識與錯字修飾交給 Groq (`whisper-large-v3` + `llama3-70b-8192`)；而將強大的 Gemini API 額度保留給需要深度思考的備課與分析任務。

#### 2. UI 介面與多螢幕防護 (4 螢幕 VESA 陣列)
- **座標鎖定防呆**：由於使用者的桌面是由四台螢幕組成的陣列，所有的浮動 UI（如「錄音中...」提示、系統匣圖示、設定視窗）**必須強制鎖定顯示於主螢幕 (Primary Display) 的絕對座標**。嚴禁視窗生成於延伸螢幕邊緣，以免視窗迷失。

#### 3. 快捷鍵與輸入法防禦機制
- **避讓機制**：觸發錄音的快捷鍵 (預設 `Alt + Space`) 必須實作嚴謹的鍵盤 Hook，確保絕對不會與使用者常駐的 **WeType 輸入法** 或是 **XMind 8** 產生熱鍵衝突。
- **Timeout 解鎖**：必須具備 Timeout 自動解除鎖定的防呆機制，避免程式異常時造成鍵盤全域鎖死。

#### 4. 專屬語意修飾 Prompt (高中地理教師情境)
- 為了達到最高的修飾精準度，送給 LLM 的 System Prompt 必須針對使用者身分特化：
  > 「使用者是一位高中地理教師，內容常涉及『探究與實作』課程、SDGs、GIS 系統操作、以及高中地理專有名詞。請自動過濾掉口語贅詞，並直接輸出修正後的純文字，絕對不要包含任何解釋或開場白。」

#### 5. 字典檔替換防過度糾正 (Over-correction Guardrails)
- **問題現象**：當向 LLM 下達「極度嚴格強制替換同音字」的指令時，如果使用者說出字典中沒有的詞彙（如「林志強」），LLM 會為了強行套用規則，將其強制篡改為發音略為相似的字典詞彙（如「林政弘」）。
- **防呆心法**：在 System Prompt 中，除了提供字典外，必須同時加上明確的**安全護欄警告**：「如果語音辨識的發音跟字典明顯不同，請保持原樣，絕對不可強行套用字典！」以避免 AI 過度積極干預導致語意扭曲。

#### 6. 單句無句號優化 (Single Sentence Punctuation Optimization)
- **設計決策**：為了方便使用者在輸入短片語或人名後接續打字，已在 System Prompt 中加入「單句無句號」規則。只要輸入的是「單一一個句子」（中間無逗號斷句），AI 就絕對不會在句尾加上句號；若為兩句以上的複合句，才會加上句號，完全符合人類直覺。

#### 7. 全域熱鍵與 UIPI 權限防禦 (UI Privilege Isolation)
- **問題現象**：當程式以一般權限執行時，若使用者在「系統管理員權限」的視窗 (如 CMD 或 Antigravity) 內按下快捷鍵 (F9)，會因為 Windows UIPI 安全機制而導致全域熱鍵失效。
- **防呆解法**：`start_admin.bat` 腳本已加入**自動提權 (UAC)** 機制 (`net session` 判斷與 `getadmin.vbs` 呼叫)。確保使用者手動雙擊啟動時，會自動彈出權限確認視窗，獲取最高權限後再啟動 Python 程式，藉此穿透 UIPI 限制。

#### 8. 🚫 LLM 過度貼心防呆：專有名詞的擴充與翻譯
- **現象與問題**：遇到英文專有名詞 (如 `Skill`) 或縮寫 (如 `SOP`) 時，LLM 常會出於「假貼心」自動翻譯或擴充全名。即使一般性地要求「保留英文」，LLM 仍可能自作主張加上括號解釋。
- **防呆心法**：在 System Prompt 中，必須採用**「極度嚴厲且具體點名」**的方式禁止（例如：絕對不可寫成「技能(Skill)」或「標準作業程序(SOP)」）。

#### 9. ⚠️ Whisper API Prompt 896 字元長度硬上限防呆
- **問題現象**：當自訂字典整合擴充至 170+ 個詞時，Whisper API 對 `prompt` 參數有嚴格的 896 字元上限，溢出時引發 HTTP 400 崩潰。
- **防呆心法**：建構 Prompt 時採「單詞逐一累加」，並設立 **350 字元安全閥**，嚴格封殺溢出錯誤。

#### 10. 🛡️ 多模型動態探測與多金鑰自動輪替 (Multi-Tier Resilience)
- **問題現象**：Groq 官方無預警下架舊模型（如 8b-instant 遭遇 404 Deprecated）。
- **防呆心法**：呼叫 `client.models.list()` 動態探測線上活躍模型，過濾非對話型號；支援多組 API Key 自動輪替（遇 429 切換下一把）；第三層串接 Google Gemini 雙引擎極限備援。

#### 11. 💾 RAMDISK 記憶體磁碟 (`S:\NoType_Audio\`) 音檔防積壓
- **防呆心法**：所有音訊 `.wav` 檔一律儲存於 `S:\NoType_Audio\`。每日重開機時自動抹除，免除手動清理硬碟空間的負擔。清理 S: 磁碟時，`New.txt` 與 `New.WRI` 常駐白名單絕對不可刪除。

#### 12. 🧠 主動回饋式自適應學習庫 (`corrections.json`) 與三按鈕人因設計
- **防呆心法**：建立 `corrections.json` 映射庫與 `dictionary.txt` 雙軌連動，輸出前物理層強制校正。
- **人因設計**：極速糾錯教學浮窗採用清晰的「三大獨立按鈕」：`[ 僅本次替換 (Enter) ]`、`[ 永久學習並替換 (Shift+Enter) ]`、`[ 取消 (Esc) ]`，徹底消除核取方塊帶來的認知混亂。

#### 13. 🪟 Windows 視窗焦點搶奪與 Word 快捷鍵衝突防呆 (Win32 Focus & Smart Re-selection)
- **問題現象一 (Word 格式衝突)**：在 Word 中按 Shift+F8 後，底層若殘留 Shift 狀態，`Ctrl+V` 會被 Word 視為 `Ctrl+Shift+V`（貼上格式），導致文字吞掉。
  - **解法**：貼上前強制以 `pyautogui.keyUp` 釋放所有 Shift/Ctrl/Alt 修飾鍵。
- **問題現象二 (視窗焦點遺失)**：彈窗關閉時焦點懸空。
  - **解法**：彈窗前記錄 `target_hwnd`，關閉後利用 Win32 `AttachThreadInput` + `SetForegroundWindow` 強制把焦點拉回 Word。
- **問題現象三 (反白選取瓦解與向左自動補選)**：焦點切換時，Word 會瓦解反白、游標縮在錯字後方，直接貼上會造成「字尾黏貼」（例如：`你要找的[這個]`）。
  - **終極解法**：貼上前探測剪貼簿，若反白已瓦解，程式**全自動動態根據 `len(wrong_text)` 向左連按 `Shift + ←` 重新將錯字反白起來**，隨後覆蓋替換！

#### 14. ✂️ 意圖理解：自我改口修剪 (False-Start Pruning)
- **問題現象**：講話口誤自我修正（如「約明天下午三點…啊不對…改五點好了」）時，傳統語音辨識會一字不漏打出全部過程。
- **防呆心法**：System Prompt 注入改口標記識別（`啊不對`、`更正`、`改為`），自動拋棄前半句被否定的語句，保留主詞受詞縫合，只輸出拍板結論（`明天下午五點`）。

#### 15. 🔒 Windows 原生 Mutex 單實例防多開互斥鎖 (Single-Instance Guard)
- **問題現象**：背景意外多開 Python 實體時，多個鍵盤鉤子同時監聽，會導致一次辨識重複輸出兩次文字（幽靈雙胞胎）。
- **防呆心法**：`main.py` 啟動首行宣告 Windows 原生 Mutex `CreateMutexW(None, False, "Local\\NoType_Typeless_Scribe_SingleInstance_Mutex")`，偵測到 `ERROR_ALREADY_EXISTS` 即安靜退出；`start_admin.bat` 啟動前強制清剿舊實體。

#### 16. 🧹 強力去贅字清剿 (Mute Fillers)
- **問題現象**：思考停頓時無意識說出的「呃、那個、其實、就是、然後」若被保留，會使文字零碎吵雜。
- **防呆心法**：Rule 6 強制清剿無語意停頓贅詞，尤其針對臺灣口語中高頻連環濫用的「然後」進行嚴格肅清，確保輸出乾淨俐落。

#### 17. 🇹🇼 臺灣在地化慣用語物理層守護 (Taiwan Lexicon)
- **問題現象**：Whisper 訓練集偏向簡體中文，偶爾會吐出大陸慣用語（視頻、軟件、質量、算法）。
- **防呆心法**：System Prompt 嚴格在地化；後處理層以正則將「視頻/軟件/質量/算法」替換為「影片/軟體/品質/演算法」，並以負向斷言 `(?<!演)算法` 防範「演演算法」；理化關鍵詞（物質、重力、慣性、密度、kg）出現時，保留物理專有名詞「質量 (mass)」不予替換。

#### 18. 🎯 前景 App 語氣自適應感知 (App-Aware Context)
- **問題現象**：單一語氣無法跨軟體滿足需求（LINE 聊天太嚴肅像公文，Outlook 寫信太隨便失禮）。
- **防呆心法**：按鍵按下當下，0 毫秒 Win32 API 探測前景視窗 PID 與進程名稱，動態注入 `chat` (LINE/Discord)、`email` (Outlook/Teams)、`doc` (Word/Obsidian)、`code` (VS Code/Terminal) 語氣模板。

#### 19. 📝 智慧垂直條列清單排版與右手 Alt 雙模態熱鍵
- **問題現象**：口述採買清單或交辦事項擠在同一行難以閱讀；原 `F9` 位於頂端且筆電需按 Fn 鍵，手感不便。
- **防呆心法**：
  - 偵測到清單或交辦詞彙時，強制排版為 `\n1. `、`\n2. ` 垂直數字清單。
  - 將熱鍵遷移至鍵盤右手邊 Alt (`alt_r` / `alt_gr`)，支援「單擊切換 (Toggle)」與「長按放開 (Hold-to-Talk)」智慧雙模態，大拇指盲打順手流暢。
